# Studio — the design every page wears (reference)

Read this before touching any page. Studio is finished and is the only design:
there is no per-page switch any more (`ui.studioPages` and `src/lib/studio.ts`
are gone) and the old versions of rebuilt pages were deleted.

## 1. What Studio is, and where the spec lives

The owner showed the Superpower health app and asked for Oracle to look and work
like it: a big title, two equal summary cards (dark, textured, with rings, arcs
and bars), then full-width rows or the record, with a floating footer instead of
a sidebar. Every number is a door; a row click opens a side panel; a record is a
page that fits the screen.

**The mockup is the specification.** Source: `design/studio-mockup/` (README
there; boards in `boards/*.dc.html`, generated by `gen/p_*.py` on the kits
`gen/kit.py` / `gen/mkit.py`). Published canvas:
https://claude.ai/artifact/KtgVP9gLJr4yAcceLwJtxt . Key boards:
- `Plan` (phases), `Coverage` (every page and where each feature went),
  `FeatureMap` (Tasks in detail), `Main` / `Expanded` (task list and record).
- `QuickAdd` / `NewTask` / `CreateEdit` (create and edit), `Footer`, `GoTo`,
  `Ask`, `Notifications`.
- One board per page (Home, Calendar, Event, People, Person, Companies, Company,
  Outbox, Recurring, Notes, Note, Insights, Assets, Attendance, Supplies,
  Cleaning, Announcements, Ori, OriBuilder, Settings); Files is
  `files/files.html`.
- `M_*` = phone and tablet (iPhone 15 393×852 + iPad Air portrait 820×1180;
  iPad landscape ≥1024 is the desk); `M_Rules` holds the phone rules.
- `S_*` = staff (`gen/p_staff.py`; S_Rules/S_Home/S_Tasks/S_Task/S_Profile).
- Email: `email/reminder.html`. Serve locally: `studio-mockup` in `.claude/launch.json`.

**Compare at the mockup's own size**: set the tab to 1440×900 and read the
generator's exact numbers, section by section, before calling a page done.

The rules that still hold: **saving does not change** — Studio screens call the
same actions and cores as before; a one-field edit is a thin wrapper over
`updateTaskCore` (a PATCH), never a second writer.

## 2. How a Studio page is built

**The kit** — `src/components/studio/kit.tsx`: `StudioScope` (the `.studio`
wrapper), `StudioHeader`, `StudioCardRow` (becomes `StudioSwipeRow`,
`swipe-row.tsx`, on a phone), `StudioCard` (dark/light + textures
`rings|contour|hatch|dots|paper-dots|paper-rings`), `CardHead`, `BigNumber`,
`Ring`, `Arc`, `Dot`, `StudioPill`, `stBtn` (button looks) and `stFloatBar`.
- **The two cards under every title are ONE height** (26 Sept 2026), set in
  `swipe-row.tsx` (`.st-cardrow`): 250px desk, 290px tablet, ≥248px phone.
  **Pages never set their own** `lg:h-[…]` on `StudioCardRow` — make a card's
  content fit instead. The row also dresses dark cards (`data-st-dark`, set by
  `StudioCard`): the left one wears `/tex/flow.svg` (flowing lines drawn once,
  not tiled), the right one the Unread-updates rings — `globals.css`.
- A "+N" chip beside faces carries `data-face` too.
- Tasks views: List · Board · Calendar · Timeline (the Cards view was deleted
  26 Sept 2026; `?view=cards` opens the List).
- **The search/filter bar is the same floating row on EVERY page** (owner,
  26 Sept 2026): `stFloatBar.page|sticky` + `stFloatBar.box`, last in the page.
  Both wrappers carry `-mb-[84px]` so the bar never rises off its place (and
  over content) at the end of the page — main's foot already keeps 96px for it.
  A panel sized to the window (`useFitFrame`) passes `bar: true` to leave room.
  Never put a page's search in its header.
- **Board** (`board-view.tsx`): the stages in one line on top (also drop
  targets), a fixed-height column under each; the height is MEASURED so the
  whole board fits above the bar at the page's end. The drag is pointer events,
  not HTML5 drag-and-drop — mouse drags on move, a finger holds 320ms first; a
  still mouse press / a finger held and released peeks.
- Every `PersonFace` wears a line ON its edge (an `outline`, `[data-face]` in
  globals.css) — not a ring with a gap. Toasts float above the bar and footer.
- **Phone sheets drag** (`studio/drag-sheet.tsx`: `useDragSheet` + `SheetGrip`):
  the Filter panel (`base: "content"` — as tall as the tab it opened on, held
  for every tab), the task preview (below lg; grows to "full" before opening
  the task page) and the task page's "…" menu. Use it for any new phone sheet.
- **Overlays a page draws go through `BodyPortal`** (`kit/body-portal.tsx`) —
  drawn inside the page they sit under the Studio footer.
- **Board on a phone**: a row of stage buttons and the chosen stage's cards
  full width; hold a card and drop it on a stage.
- **Report**: `getBriefCached` (`lib/reports/brief-cache.ts`, 1 min) serves the
  sheet and both PDF routes; logos are shrunk to 192px (`pdf-logos.ts`); the
  sheet builds the PDF in the background and Download fetches then saves or
  shares it (`fetchPdf`/`savePdf`) — never a page navigation.
- `stFloatBar.sticky` — a search/filter bar in a panel that ends at the footer
  (Tasks); `.fixedLg` — inside a panel that stops short of it; `.page` — on a
  page where the whole window scrolls (Notes, Assets, Supplies). Always 12px
  above the footer. Never hand-write a `bottom-…`.
- `use-fit-frame.ts` (`useFitFrame(ref, { enabled, minimum })`) sizes a grid to
  the room left in the frame so columns scroll inside themselves and the page
  does not. Used by the task record, Home, Calendar, People, Person, Companies,
  Outbox.
- `sheet.tsx` — `StudioSheet`, THE pop-up for a form on a Studio page
  (`.st-sheet`, rises from the footer, Esc / click-outside).
- `tasks/cells.tsx` — `StudioChoiceMenu`, THE Studio pick-list (status,
  priority, risk, category, escalation, company, and elsewhere). `StudioMenu`
  (header dropdowns) is in `tasks/controls.tsx`.
- `face.tsx` — `PersonFace`: every person circle in Studio. Blobatar
  (`blobatar` + `@blobatar/react`), colour by ROLE, expression by WORK
  (`src/lib/people/face-mood.ts`, tested). Moods come from `/api/faces`, memoised
  5 min per server and filtered per viewer.
- `people-pick.tsx` — the people picker (+ sheet, new task, a task's people).
- `subtasks.tsx` — `TaskSubtasks`, `DraftSubtasks` and the exported `ListShell`
  (also the staff to-do card).
- `foot-note.ts` — `useStudioFootNote()`: a page's line in the footer, tied to
  the path so it never lingers.
- `studio-paths.tsx` — `StudioPathsProvider` / `useStudioPaths()`: every link in
  the shared People / Companies screens asks it (owner paths, or `/portal/*`
  for staff; `paths.staff` switches the staff limits on).
- `oops.tsx` (404/error), `auth/studio-sign-in.tsx` (`/login` + `/portal/login`).
- `src/components/ui/checkbox.tsx` — the tick box. ⚠️ `@/components/ui` still
  means the older FILE `src/components/ui.tsx`.

**The frame** — `shell.tsx` (client) + `shell-server.tsx` (owner/director/
manager) + `staff-shell-server.tsx` (staff):
- Footer: next deadline · Home · ‹ page › · Settings · Ask/search · bell ·
  "+ New". The page pill steps on mouse wheel / trackpad and loads only where
  the wheel stops (420ms); a sideways swipe on a phone moves one page;
  neighbours are prefetched.
- Go-to panel: every page, grouped, type to filter, Enter goes; ‹ › as key caps,
  "Search every record" (hidden for a director), the one light/dark toggle.
- The page order is `src/lib/nav/studio-nav.ts`, derived from `nav.ts`
  (longest-path match, wrap-around; tested). `directorStops()` and
  `staffStops()` there are the director/manager and staff menus.
- The shell listens for `window` event **`studio:new` {tab}** to open "+ New" on
  a given tab (People and Companies headers use it; `/people?new=1` too).
- The shell mounts `ReportSheet` and `NavProgress`.

**CSS** — `src/app/globals.css`:
- `.studio` holds the tokens (`--st-*`, light and `.dark .studio`), the
  `st-tex-*` textures and the `st-pop`/`st-rise`/`st-draw` animations
  (reduced-motion safe). Studio keeps circles (`.studio .rounded-full`) and its
  own 12/13/14px type scale whatever the Desk density. Geist + Geist Mono are
  loaded in `layout.tsx` as CSS variables.
- Everything about the frame keys off **`body:has([data-studio-frame])`**: page
  colour, `main`'s padding, `--page-foot` / `--page-top`, and sticky bars
  (`data-sticky-top`, `data-sticky-foot`, `data-savebar`) clearing the frame.
  The staff portal and sign-in screens share the layout but drop the frame, so
  they are untouched.
- `--foot-h` (64px) + `--foot-safe` (what is left of the iPhone home bar): every
  "above the footer" offset is `calc(var(--foot-h)+…)`, never a literal.
- **Desk controls inside Studio take Studio's look by REDEFINING DESK'S TOKENS**
  on `.studio`, the footer, the Go-to panel and — while a Studio page shows —
  every direct child of `<body>` (where pop-ups portal). Do not fork
  FluidSelect / DatePopover / Combobox. `data-field-label` on Desk labels lets
  Studio drop the capitals; `Button` carries `data-variant` and `Switch`
  `data-on` for the same reason.
- `.st-sheet` — the theme-following sheet (`--sh-*` light + `.dark .st-sheet`,
  `.st-sheet-dots`): search, notifications, "+ New", Go-to, `StudioSheet`.
  `.st-dark-chip` reads `var(--sh-fg, #F2F2F0)`, so it also works on a page's
  own dark band.
- `.st-desk` + `.st-panel` — an older Desk panel inside a Studio card (greys,
  hairlines, control box, sentence case; `.st-panel` dissolves its own box).
  Reuse this before rewriting a panel.
- `.st-form` gives Desk dropdowns and date pickers inside a Studio form the
  `.st-field` box; wrap a `DateInput` (`src/components/forms/date-input.tsx` — use it
  instead of `<input type="date">`) in `<span className="st-date block">`.
- `.st-settings` — Settings' masonry columns. `[data-st-menu]` — a dropdown
  that becomes a full-width panel at the foot below 640px (tag every new popup).
- `--st-muted` is a DARK grey (#676A70) for white surfaces; every dark surface
  redefines it light. Don't put #8E9197 / #A3A6AB text back on either.

**Lists and forms**
- `RecordList variant="studio"` (`src/components/kit/record-list.tsx`) — looks only;
  same column engine, sorting, bulk, export, `activeKey`, `lead` (quick-add
  row). Filters still go through `useUrlFilters`.
- Some shared Desk components still take a `studio` prop because the other look
  is used elsewhere (the portal, a Desk panel): `PersonForm`, `JourneyChecklist`,
  `AttendeePicker`, `EventAttachments`, `DeadlineEditor`, `PersonPackPanel`,
  `RecurringTaskSheet` (`portal-recurring-tasks.tsx`), the command palette.
  `PortalConversation`, `SimilarTasks` and the bell take `variant="studio"`.

## 3. Page by page

**Home** — `src/app/_hub/studio-home.tsx` (server: every figure, from
`getAllTasks`, with Tasks' own meaning of late / due soon) +
`src/components/studio/home/studio-home.tsx` (layout; also staff, via slots).
- Hero: a bar per open task (quiet → moving → due soon → late), height by
  priority; each opens its task. Live announcements ride in the hero line.
- Due card (Today / This week) + three turning cards (‹ ›, dots, swipe, ←/→):
  Tasks, People, Companies & the day — incl. Latest activity (`lib/tasks/activity.ts`),
  Team today, Documents, Controls held (optimistic, rolled back on failure).
- "Send the Director Brief" asks twice. Phone: hero + `PhoneFolds` (open state in
  localStorage `studio.home.folds`).

**Tasks list** — `src/app/_hub/tasks-section.tsx` computes everything and
renders `StudioTasks` (`src/components/studio/tasks/studio-tasks.tsx`).
- Cards: `insights-card.tsx` (Overview / By company / By person) and
  `update-card.tsx` (every UNREAD update, three a page; latest three when none).
- Rows via `src/app/task/_views/table-view.tsx`: dot + word status, faces,
  two-line latest update, deadline in coloured words, ☆ (`toggleTaskStar`, one
  settings row `ui.starredTasks`; starred lead unless grouped). The tick box sits
  in the left margin. A row's TITLE and LATEST-UPDATE cells link to the task;
  the rest picks it. Phone rows are `PhoneTaskRow`.
- Bottom bar `StudioSearchBar` (live search, 300ms, replace-not-push, typing ref):
  search · company · All / On track / Due soon / Late (`flag=on-track`). Quiet,
  Unread, Done are in the `FiltersButton` panel. List order is most recently
  touched first.
- Picking is `StudioPickProvider` state (`tasks/pick.tsx`), NOT the URL; Esc
  clears. Board / Calendar / Timeline / Cards are the same body components.
- Bulk bar: select-all is a toggle; Close and Escalate confirm for >1 (no Undo).

**Side panel** — `tasks/task-panel.tsx`: fixed right, 400px, not a modal; from
`xl` the page makes room (`:has([data-task-panel]) main { padding-right: 440px }`);
below it floats; on a phone it is a sheet above the footer (the quick-update
sheet). It loads `/api/task-detail`, which stamps the owner's view (marks read).
↗ grows the panel to the frame, then navigates (page prefetched on open).

**Task record** — `/task/[code]`, `TaskRecordPage` in `src/components/tasks/task-drawer.tsx`.
- Three columns fitted to the frame: Details (`tasks/details.tsx`, every value
  edits in place through `patchTaskField` → `updateTaskCore`, audited, Undo;
  moving company follows the new code), the conversation (oldest-first bubbles,
  writing box pinned at the foot), People / Share / Similar.
- Waiting on = `StudioBlocker` (`tasks/blocker.tsx`). Owner can edit/take down
  an update (`adminEditUpdate` / `adminDeleteUpdate`). Notes tab is owner-only
  (`ownerView` from `/api/task-detail`). Subtasks tab carries a count.
- **No loading screens**: `src/lib/tasks/task-detail-cache.ts` (stale-while-
  revalidate), filled by the panel, the record and read-ahead (hovered row after
  160ms, neighbours of the open task). `task/[code]/loading.tsx` draws the record
  from it; `task/loading.tsx` returns null. ‹ › uses `history.pushState` and the
  record reads its code from the ADDRESS.

**New task / "+ New"** — `studio/quick-add.tsx`: one card, a tab per
`creatables()` entry, opening on the tab that fits the page. Task
(`QuickTaskPane`), Person (`people/quick-person.tsx` → `createPerson`), Company
(`companies/quick-company.tsx`) and Document (`files/quick-document.tsx`) are
full panes; Note, Event and Announcement hand on to their own forms. The task
pane stays MOUNTED while other tabs show. Options are preloaded in the
background (`preloadQuickAdd`). "Create and add another" = Ctrl+Enter.
- `/task/new` = `StudioNewTaskPage` (`tasks/new-task.tsx`), the record as a
  draft; ONE writer `createTaskStudio` → `createTaskCore`, then instructions as
  the first update, then "Also create in" copies. A repeat not due today is saved
  as a rule.

**Recurring** — `/task/recurring` → `studio/recurring/studio-recurring.tsx`,
same four actions in `src/app/task/recurring-actions.ts`.
- `nextOccurrences()` in `src/lib/tasks/recurring-task-rules.ts` (tested) is built on
  `occursToday` and skips today once `lastFiredAt` ≥ 09:00, so the page never
  promises a day the job won't act on. Remove asks twice.

**Calendar** — `src/app/calendar/calendar-board.tsx` (one component: hooks,
filters, views, `EventForm`, saves).
- Opens on Month; six rows share the height. Click a day PICKS it (left card
  lists everything, `StudioDayList`); double-click opens Day. The picked day is
  in the address (`?day=`), set by `replaceState`.
- Next 7 days = `StudioNext7Bars` (stacked bars, hover card above the bar).
  Week/Day = `StudioTimeGrid` (click an empty hour → new event there). Agenda =
  `StudioAgenda`. Layer colours in `STUDIO_LAYER`; `--st-cal-*`, `.st-cal-chip`.
- Event screen (board Event): dark action bar, two columns, clash footer.
  `useEventActions` is the ONE copy of an event's actions and their dialogs;
  `StudioReadCard` shows what was read from a ticket.
- Overlay links come from `src/lib/calendar/calendar-overlays.ts` and are `ReturnLink`s.

**People** — `studio/people/studio-people.tsx`; person `studio-person.tsx`.
- Columns (per company, `PeopleColumns`, slides ‹ ›) is the default for everyone;
  Grid via `lay`. Filters through `useUrlFilters`. Click picks into the right
  card, double-click / ⤢ opens; on a phone a click opens. Select = bulk.
- Person: band, tabs Overview · Tasks · Documents · Journey · Equipment · Notes
  · History · Edit (tabs by `replaceState`). Overview and Edit fit 1440×900; only
  a LIST scrolls, never a column. Edit = `PersonForm studio` in three columns with
  `PortalEditor` (`people/portal-editor.tsx`) applied AFTER the person saves
  (`applyPortalDraft`).
- A director's reach is one choice: every company / only their companies
  (`setPortalLevelWithReach`, `grantPortalAccessWithReach`; `directorFollowsCompanies`
  + `refreshDirectorScope` in `src/lib/portal/portal-access.ts`, wired into
  `updatePerson` and bulk company). A "custom" scope is shown and left alone.
- "Remind about open work" = `useRemindPerson` (`people/remind.ts`): an Outbox
  draft, never sent. Equipment = `people/person-equipment.tsx`.

**Companies** — `studio/companies/studio-companies.tsx` (hub, incl.

**Files** — `/files`, `src/components/files/files-app.tsx` (board

## 4. Who sees what

- **Owner**: every page above.
- **Directors and managers** — the same Home, Tasks, task, People, Companies,
  Calendar, Files, Outbox, Announcements over their companies. They are a
  `Viewer` (`src/lib/auth/viewer.ts`, `kind: "director"`, `role` says which;
  `getViewer`, `guardOwner` / `guardViewer`). Managers' capabilities equal
  directors'; a director's reach can be all / own / chosen companies, a manager
  always sees their own. Read `memory/portal_unification_plan.md`.
  - An old portal address is sent on by the PORTAL LAYOUT
    (`studioPathForDirector` in `src/lib/portal/director-routes.ts`, tested; the proxy
    passes the address in `x-cos-path`), before the old frame paints.
  - `/portal/profile` (both) and `/portal/cleaning` (managers) stay under the
    portal in the Studio frame the portal layout draws; a manager checks in on
    Profile (`CheckinPanel`).
  - "You" (the owner) reads "Administrator" to them; a director's thread puts
    only THEIR posts on the right. No ⌘K palette for directors.
- **Staff and the receptionist** are NOT a Viewer (a new kind would fail open in
  every `kind === "director"` check). Their pages stay under `/portal/*`, read
  through portal-auth (`visibleTaskIds`, `personCanSeeTask`) and write through
  the portal actions. `isStaffLikeRole()` (staff | receptionist; UI only —
  permissions read the real role and `caps`).
  - Every portal page wears the Studio frame (26 Sept 2026): the old chrome,
    `PortalFrame`, `isStaffStudioPath()` and the old launch splash were deleted
    with `/portal/outbox` and `/portal/insights` (now redirect stubs).
    `/portal/task/new` is still the old form, inside the Studio frame.
  - Footer: `StudioShell` served by `StaffShellServer`, `staffStops()`; "+" =
    New to-do (`/portal?todo=1`).
  - Home = `StudioHome` with slots (check-in top right, to-do card
    `home/staff-cards.tsx`, "How I did in <month>" → Profile #kpi). Tasks =
    `src/app/portal/(app)/tasks/staff-tasks.tsx` (rows open the task page, no
    side panel). A task = `studio/tasks/staff-task-record.tsx` (Send for review,
    I'm blocked, Complete only if they raised it; edit only with
    `caps.manageAnyTask`). Profile = `studio/profile/staff-profile.tsx`.
  - Shared screens with staff limits: `src/lib/portal/staff-colleagues.ts`
    (`staffColleagueIds`, `forStaff` blanks workload/private fields),
    `people/[id]/staff-person.tsx`, `companies/[id]/staff-company.tsx`,
    `meetings/staff-calendar.tsx` (read-only), all under
    `src/app/portal/(app)/`. Faces: calm for staff, moods only for their own

## 5. Traps

- ⚠️ **"White borders" = `* { border-color: hsl(var(--border)) }`**, UNLAYERED,
  so it beats every Tailwind border-colour utility. Studio surfaces (`.studio`,
  `[data-studio-foot]`, `[data-studio-goto]`) are excluded and get a layered
  default. A Studio pop-over portalled to `<body>` must carry `studio` or one of
  those attributes, or its borders go grey.
- ⚠️ **`.studio { color: var(--st-ink) }` is unlayered too**: a dark surface that
  carries `studio` needs an inline `color`, or inherited text is dark on dark.
  The Calendar's hover card is deliberately NOT `.studio` for this reason.
- ⚠️ **globals.css's unlayered `input { color; border; background }`** beats
  utilities — a light input on a dark surface needs inline style.
- ⚠️ **Sticky only works because body is `overflow-x: clip`.** `overflow-x:
  hidden` made body a scroll box that never scrolled, so sticky stuck to body.
  Don't put `hidden` back.
- ⚠️ **`scrollbar-gutter: stable` is on `<html>`** — with `clip` the VIEWPORT
  scrolls, not body, so a body-only gutter reserves nothing.
- ⚠️ **The frame is an illusion.** The document still scrolls; a fixed,
  click-through ring with a 100vmax box-shadow paints outside a rounded
  rectangle. Making `main` a scroll box would break every "back to where you
  were" (they read `window.scrollY`).
- ⚠️ **A layout does not re-render between its pages.** While old and Studio
  portal pages coexisted, the frame had to be picked on the client from the
  address (deciding from a request header froze the first page's frame). Every
  portal page is Studio now, so the layout draws one frame — if two frames ever
  coexist again, pick on the client.
- ⚠️ **Tabs and a picked day use `history.replaceState`, not the router.** The
  pages are dynamic; `router.replace` re-read the whole record on every click.
  Next keeps `useSearchParams` in step.
- ⚠️ **Read-ahead passes `peek=1`** to `/api/task-detail`, which otherwise marks
  the task read.
- ⚠️ **Escape, one layer at a time.** Menus/pickers `preventDefault` on Escape;
  the event screen and `StudioSheet` listen on WINDOW so a menu gets first
  refusal.
- ⚠️ **Don't use Tailwind `dark:` for Studio colours** — use `--st-*` tokens under
  `.studio` / `.dark .studio`.
- ⚠️ **`st-pop` animates `transform`** — position a popover with `bottom`, not
  `translateY(-100%)`, or the animation wipes the offset.
- ⚠️ **Never branch RENDERED output on `useMediaQuery`** — a different list on the
  client is a hydration error. CSS for what shows, the hook for behaviour.
- ⚠️ **Never define a component inside a component's render** — it remounts every
  render and inputs lose focus while typing.
- ⚠️ **Key an effect on PRIMITIVES, not `useFace()`'s object** — a fresh object
  per render restarted the peek timer every render (241 faces, "Maximum update
  depth"). Blobatar's `expression` takes an OBJECT from `blobatar/expression`;
  `animate` needs `blobatar/motion.css`, gaze `blobatar/gaze.css`. Task-row
  peek (face 1s, initials 3s) is pure CSS (`st-face-peek`).
- ⚠️ **The Go-to panel's selected item is INVERTED** — its icon tile must be a
  tint of the item's own text colour (`color-mix(var(--sh-on-fg) 16%)`).
- ⚠️ **Cards handed from a server page to a client component as an array need keys.**
- ⚠️ **Use the company's `code_prefix`** for anything that "sets the code", never
  the name (Furaha Innovation is CC).
- The old Aurora launch splash (`app-splash.tsx`, `SplashGateScript`) was
  deleted 26 Sept 2026 — it only ever played on old-design portal pages, and
  none are left.
- ⚠️ **The dev server sometimes misses a file edit** (seen after a production
  build in the same session): check the served stylesheet for your new selector
  before believing a visual; a fresh append to the file woke the watcher.
- ⚠️ **Python heredocs** turned `\b` into a BACKSPACE byte in a regex — write JS
  regexes with the Write tool, or check with `od -c`.
- ⚠️ **Every server action starts with its guard** (`guardOwner` /
  `guardViewer` / `ownerOnly` / a portal check). ~50 were found without one; a
  server action is callable from any page, so the proxy gate is not enough.
- Browser pane: forces light (use `resize_window colorScheme: dark`); blank
  screenshots while hidden; the owner signs in himself — never type it.
