01

The idea

Why the system exists

A single Chief-of-Staff command centre that runs the day-to-day operations of Oracle Consultancy and its seven portfolio companies — for one operator, replacing a sprawling Excel workbook with a living system that has a memory.

The brief was not "digitise the spreadsheet" but "give the operator a brain": capture work and never lose its history, keep people and compliance current, remember every meeting, and surface the whole portfolio on one glanceable brief — so decisions are made from one source of truth.

Design principles

The rules everything follows
PrincipleWhat it means in practice
Reuse, don't duplicateOne capability underpins many features: Documents power compliance, tasks/todos power checklists, OECR underpins assets, Outbox powers messaging, Home/Brief surface signals. New features extend existing tables rather than inventing parallel ones.
One design language — "Aurora"Every page, dialog and form shares the same liquid-glass surfaces, single blue accent, centred layout, iPhone-style toggles and calm motion. Learn one screen, know them all.
Single source of truthAppend-only history and audit trails; facts are never overwritten (the fact ledger keeps versions). Access can be revoked but data is never deleted.
Glanceable, every-number-a-doorCounts and figures are clickable; the system shows where to look, then lets you act.
Portal parityThe staff portal is first-class — it shares visuals and motion with admin, dropping only what would expose other people's data.
Grounded intelligenceAI works from your records and cites them; it never invents data, and degrades gracefully when switched off.
03

How it all fits together

Architecture

A single Next.js application, server-rendered, talking to one Postgres database, hosted close to that database, with a thin AI layer bolted on the side.

The stack

LayerTechnology
AppNext.js 16 (App Router), React 19, TypeScript 5 — one codebase serves admin + portal
DataSupabase Postgres via the pooler (port 6543); Drizzle ORM + postgres.js; supabase-js for newer write paths
StylingTailwind v4 tokens (globals.css) + the Aurora component kit
AIGroq Cloud (openai/gpt-oss-20b / openai/gpt-oss-120b) for language; pgvector + an embedding Edge Function for semantic search
HostingVercel, functions pinned to the EU region to sit beside the database (kills transatlantic latency)

Request flow

Browser→ Edge gate (proxy.ts)→ Server component / action→ Postgres

Every request passes the edge gate in src/proxy.ts (the Next-16 proxy convention), which checks the signed session cookie before any admin or portal page renders. Reads and writes happen in server components and server actions — there is no separate API tier to keep in sync.

The AI layer

AI is additive, not load-bearing. A safety harness (src/lib/ai-json.ts) wraps every Groq call with retries, timeouts and JSON guards; a master switch turns it all off cleanly. Semantic search indexes tasks, documents, meetings and people into pgvector and blends vector hits with full-text search.

Configuration that must not changeprepare:false + max:1 in src/db/index.ts (PgBouncer transaction mode); the pooler port 6543; the secret() derivation must stay identical across proxy.ts, admin-auth.ts and portal-auth.ts; all wall-clock columns are timestamptz written as UTC and shown in local (Dar es Salaam, UTC+3) time.

Roles & the access model

Who can do what

Two separate worlds, two separate cookies: the owner's admin side (cos_admin) and the staff portal (cos_portal).

RoleScopeCan do
OwnerEverything, all companiesThe full admin command centre. One password (+ optional owner identity 2nd factor) or a passkey.
StaffOwn data onlyOwn tasks, documents, attendance, leave, profile.
ManagerOwn + their team / companyTeam attendance, leave approvals, team roster, create tasks for their company.
HRAll companies (tasks)Group-wide task visibility & creation.
DirectorAll companies (operator)Board brief; create tasks/events; draft messages. Auto-routed to the board.
Data-ownership ruleRevoking access, changing a role or archiving a person never deletes their data — access control and records are independent. This keeps history and compliance intact.

Sign-in security: signed HttpOnly cookies verified at the edge; a session "generation" lets the owner invalidate all other devices by changing the password; passkeys (WebAuthn) store only public keys.

Core workflows end-to-end

How the pieces connect

A new staff member joins

Add person→Auto onboarding checklist→Auto compliance checklist→Upload docs (auto-link)→Score to 100%

A meeting becomes action

Notes / voice→Generate minutes→Extract action items→Bulk-create tasks→Linked to meeting

A document keeps compliance current

Upload / intake→Auto-link to requirement→Verify + review date→Lapses when expired→"Chase" draft

Someone leaves

Archive person→Offboarding checklist→Assets auto-returned→Data retained

A letter goes out

Pick template→Edit body→Draft→Issue (freeze letterhead + ref)→PDF

Each workflow reuses shared building blocks, so a change to (say) the compliance engine improves the person drawer, the staff portal and the Director Brief at once.

Governance controls

  • Director outreach pause/resume — a kill-switch in Settings for director messaging.
  • Audit everywhere — task history, person history, compliance events, system_events.
  • Transfer pack — board-level governance data (cap table, owners, resolutions, risks) kept current for handover.

Reliability, security & maintenance

Keeping it safe
BackupsPortable JSON snapshots (npm run db:backup/db:restore) + Supabase cloud backups (primary).
MonitoringSentry (errors only) when the DSN is set.
Performance56 DB indexes; EU-region functions; cached reference getters.
Quality42+ Vitest safety tests on money/leave/compliance/status maths; tsc type-check (4 GB heap).
DependenciesDependabot + pinned overrides (clean npm audit).
Two hard "don'ts"Never rm -rf .next while the dev server runs (corrupts the build cache). Never change the cookie secret() derivation in one place without the others — it locks sessions out.
